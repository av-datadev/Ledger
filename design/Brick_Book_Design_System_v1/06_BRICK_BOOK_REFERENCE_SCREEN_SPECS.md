# BRICK BOOK — REFERENCE SCREEN SPECIFICATIONS v1.0

These are canonical visual anchors.

## 01 OWNER DASHBOARD
Purpose: "How is the house financially doing right now?"
Hierarchy: Project identity → Total spent/budget → Project health/attention → Spending breakdown → Recent activity.
Avoid giant address cards, endless category lists and equal metric weight.
Signature module: Needs attention — unbilled, overdue, over-budget, stock anomalies.

## 02 PAYMENT ENTRY
Purpose: record a payment in seconds.
Hero: Amount.
Core: Amount, Paid to, Purpose, Date.
Secondary: Mode, Paid by, Notes, Receipt.
Capture: Scan / Speak / Write.
Signature: AI capture produces an editable structured draft.

## 03 LEDGER
Purpose: find and understand payments.
Hierarchy: Total spend → Unbilled insight → Search → Filter chips → Transaction list.
Row: Description + amount; date + person/category + mode.
Contextual: edit/delete/duplicate/link.

## 04 ACTIVITY
Purpose: understand what changed.
Chronological timeline grouped by Today, Yesterday, Earlier this week, Earlier.
Events have object-specific markers.

## 05 BOQ OVERVIEW
Purpose: understand billed vs paid vs due vs ledger spending.
Top metrics: Billed, Paid, Due, Ledger spend, Variance.
Then categories, bills and search.

## 06 BILL DETAIL
Purpose: what did this bill contain, who supplied it, what is paid and what remains?
Sections: Header, Source document, Financial summary, Line items, Payments, Stock links, History.

## 07 STOCK
Purpose: what material do I have right now?
Primary: Remaining quantity.
Secondary: Received, Given out, Category.
Actions: Received, Given out, History.

## 08 PERSON / VENDOR DETAIL
Purpose: understand the financial relationship.
Header: name + type.
Financial: Paid, Contract, Remaining, Due.
History: Payments, Bills, Activity.

## 09 CONTRACTOR DASHBOARD
Purpose: how much cash do I have at each site?
Primary: In hand.
Secondary: Received, Spent, Commitments.
Site switcher is prominent.

## 10 DATA / TRUST
Purpose: is my data safe?
Hierarchy: Saved on device → Sync → Backup → Export → Import/restore.
Technical details are secondary.

## 11 AI REVIEW
Purpose: verify extracted financial information.
Source image → Extracted fields → confidence/uncertainty → editable values → Confirm.
Never auto-save financial extraction without review.

## 12 IMPORT
Purpose: safely bring existing records into Brick Book.
Upload → Map → Preview → Resolve → Import → Summary.
