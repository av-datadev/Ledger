# BRICK BOOK — DO NOT INVENT v1.1
When a decision is unspecified, reuse the nearest existing Brick Book token, component or pattern. Do not invent a new visual language.

Never freestyle: colors, fonts, font sizes, spacing, radii, borders, shadows, button shapes, input shapes, navigation, icons, charts, AI styling, financial number formatting, semantic states, animation timing.

If a new primitive is genuinely required: explain why; propose the smallest addition; use existing semantic tokens; define anatomy/states/responsive behavior; add it to the component library.

Default: Existing Brick Book pattern > new invention.

Anti-generic test: if the output could plausibly be a generic fintech/SaaS dashboard after removing the logo, reject it and redesign.
